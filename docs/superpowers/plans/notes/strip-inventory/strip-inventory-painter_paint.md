## Traps

- **`pending_frame_diagnostics` / `PendingFrameDiagnostic` / `FrameReadyDiagnostic` are the wall barrier's frame-id plumbing**, not diagnostics. `wall_logical_frame_id` travels request → ready → `WallFrameCoordinator::note_frame_ready` → barrier completion → repaint decisions. Deleting the queue silently turns every wall frame into an unbarriered frame.
- **`note_dcomp_frame_statistics` (painter.rs:4269) is load-bearing when `commit_guard::SAMPLE_LEAD_PERIODS` is set.** Its DWM statistics query fills the shared composition grid that `paint_animation_sample_at` reads to choose the animation sample time. A stats syscall with one non-stats consumer — exactly the shape the task warned about.
- **`paint_animation_sample_at` (painter.rs:4303) computes what is drawn**, not what is logged. Keep it and `tile_monitor()`.
- **`last_render_started_at` (painter.rs:518) sits one line under `note_animation_win()`** at painter.rs:2460-2461 and reads as part of the same telemetry. It is the clock `push_due` and `renderer_is_running` run on.
- **`last_paint_animation_push_at` (painter.rs:445)** is one timestamp field among a dozen telemetry timestamp fields, but it gates whether animation values are pushed at all.
- **`display_composite_in_flight_since` (painter.rs:271)** looks like a duration sample; it is the 2-second force-release that stops a lost redraw from killing a tile for the rest of the run (`renderer_behind`, painter.rs:3299).
- **`last_gpu_memory_log_at` (painter.rs:236)** is named for the `GPUMEM` log, but the same once-a-second gate throttles `D3d11PlaneRings::expire_all_stale_demand` (painter.rs:2410-2415). Removing the Cell makes the ring reclaim run every frame or never.
- **`wall_tick_frames_produced` and `bootstrapped_pipelines`** are a counter and a set that `wall_tick::bootstrap_frame_allowed` reads to decide whether a real frame is emitted.
- **`WallFrameBarrier.first_ready_at` / `completed_at`** are printed in three log lines each but also drive `missed_deadline_at` (the 16ms barrier deadline) and `WALL_FRAME_BARRIER_RETENTION`.
- **`append_held_paint_values` (painter.rs:1515-1519)**, the source of `paint_animation_held_max`, really re-appends finished animations' values so `reset_dynamic_properties` does not blank them. Only the `max` bookkeeping is instrumentation; the loop prevents a black screen.
- **`PaintTargetsInFlight::join()`** must keep being called after `TileRenderTiming` is gone — dropping it without joining overlaps render passes.
- **`PumpSource` and `may_schedule()`** stay; only `PumpSource::note()` goes.
- **`DETACHED_DROPPED`'s increment site** sits inside the real `dispatch_detached` queue-limit check (paint.rs:1804-1807). Remove the counter, keep the limit.
- **`drop_superseded_video_frame_updates`** really drops messages; only its returned count is log-only, and 8 unit tests assert on that count.
- **`send_pending_paint_metrics_messages_after_composite` (painter.rs:2695-2790)** is upstream Servo paint-metric plumbing (FP/FCP/LCP) — English comments, no star-marked annotations. Not this fork's instrumentation.
- **`renderer_behind()` (painter.rs:3287-3315)** contains a `warn!`, which makes it look like a diagnostic; the `set_display_composite_in_flight(false)` beneath it is the recovery.
