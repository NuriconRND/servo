# GStreamer 1.28.4.100 마이그레이션 설계

- 날짜: 2026-07-22
- 브랜치: `nonstandard-media-display-port` (현재 브랜치 그대로)
- 선행 참고: [[capture-card-getusermedia-branch]](1.26.8 교체 선례), [[build-against-servo-default-gstreamer-1228]], [[gstreamer-runtime-version]], [[post-media-port-followups]](#5 1.28.4 전면 전환)

## 1. 배경 / 목표

Servo가 핀하는 GStreamer 1.22.8을 사내 커스텀 빌드 **1.28.4.100**으로 전면 전환한다. 소스는 원격 공유
`\\192.168.1.214\share\NuriconCommon\gstreamer\1.28.4.100\`(인스톨러 `.exe` + 추출본 `msvc_x86_64`).
목표는 사용자의 3가지 질문에 실증적으로 답하는 것:

- (a) 슬롯#1(`target/dependencies`) 내용물을 핫스왑했을 때 어떤 side effect가 발생하고 어떻게 해소하는가
- (b) `target/`이 없는 from-scratch 빌드에서도 1.28.4.100을 쓰려면 어떤 변경이 필요한가
- (c) 전환 후에도 기존 기능(P1~P4 + 월 + 캡처카드)이 전부 동작하는가

## 2. 현재 상태 & 스큐 분석 (실측)

| 축 | 해석 경로 | 현재 값 |
|---|---|---|
| 컴파일(pkg-config) | `servo_env.ps1`가 `SERVO_ROOT=W:\servo` 기준 슬롯#1 탐색 → 없어서 env var 폴백 | **시스템 1.26.8.101** (`C:\Program Files\gstreamer`) |
| DLL 복사(mach) | `gstreamer_root()`(windows.py:138) = multigpu 워크트리 슬롯#1 | **1.22.8** (`target/dependencies`) |
| 런타임 | mach가 exe 옆에 복사한 DLL | **1.22.8** |

→ **컴파일(1.26.8)/런타임(1.22.8) 스큐**가 이미 존재(ABI 하위호환으로 우연히 동작). 마이그레이션은
이 셋을 **전부 1.28.4.100으로 통일**해 스큐를 제거한다.

`gstreamer_root()` 해석 우선순위(빌드 링크 + 런타임 DLL 복사를 동시에 결정):
1. `target/dependencies/gstreamer/1.0/msvc_x86_64` (bin/ffi-7.dll로 탐지)
2. `%GSTREAMER_1_0_ROOT_MSVC_X86_64%`
3. `C:\gstreamer\1.0\msvc_x86_64`

## 3. 확정 결정

- 방식: **(A) 실제 마이그레이션**(커밋), **현재 브랜치** 그대로.
- 해석 메커니즘: **(1) 전용 디렉터리 + 정션** — 시스템 1.26.8 보존, 비파괴·되돌리기 용이.
- 회귀에 **캡처카드(getUserMedia) 포함**.
- 로컬 복사는 **`.pdb` 제외**.
- 접근성: 이 세션이 공유를 직접 읽기/복사 가능함을 실증(READABLE + COPY_TEST OK). 트리 = 7,251파일 / 4.3GB.

## 4. §1 — 로컬 설치 + 해석 통일

1. 공유 `msvc_x86_64` → 로컬 **`C:\gstreamer-inhouse\1.28.4.100\1.0\msvc_x86_64`** 복사(`.pdb` 제외, robocopy `/XF *.pdb`). 영구·시스템 1.26.8 미영향.
2. **env var** `GSTREAMER_1_0_ROOT_MSVC_X86_64`(머신 레벨) → 위 경로. 이게 컴파일(servo_env PKG_CONFIG 폴백)과 **from-scratch DLL 복사**(슬롯#1 부재 시 #2로 해석)를 동시에 1.28.4.100로 잡는다 = **질문 (b)의 핵심**.
3. multigpu 워크트리 **슬롯#1을 정션**: `mklink /J <worktree>\target\dependencies\gstreamer\1.0\msvc_x86_64 C:\gstreamer-inhouse\1.28.4.100\1.0\msvc_x86_64`. 현재 target이 살아있는 상태에서 1.22.8을 **비우지 않고** 오버라이드 → release `-sys` link-search 캐시가 슬롯#1 경로를 계속 유효하게 resolve(비우면 `could not open gst*-1.0.lib` 실패, 선례 기록). = **질문 (a)의 핵심 해소책**.
   - ⚠️ 기존 1.22.8 슬롯#1 내용은 정션 만들기 전에 백업(롤백용).
4. `servo_env.ps1`: 현재 `SERVO_ROOT=W:\servo`라 슬롯#1을 못 봐 env var로 폴백 → **env var를 1.28.4.100로 잡으면 그대로 통일**. (개선안: `SERVO_ROOT`를 multigpu 워크트리로 잡아 슬롯#1을 직접 보게 하는 것도 검토. `servo_env.ps1`은 servo git 밖 = 워크스페이스 로컬, 커밋 안 됨.)
   - PKG_CONFIG_PATH는 반드시 **forward-slash**(1.28.x lld-link `could not open 'gstreamer-1.0.lib'` 함정 방어 — 이미 반영됨, 재확인).

**결과: 컴파일·DLL복사·런타임 전부 1.28.4.100.**

### 5.2 플러그인 목록 (`components/servo/gstreamer_plugin_lists/windows.rs.in`)

- **현재 등록분 전부 1.28.4.100에 존재 확인됨** — 무회귀(gstd3d11, gstwasapi, gstrtsp, gstudp, gstrtp, gstavi, gstasf, gstflv, gstmpegtsdemux, gstisomp4, gstmatroska, gstlibav, gstplayback, gsttypefindfunctions, gstvideoconvertscale, gstcoreelements 등).
- **캡처카드 회귀를 위해 카메라 소스 플러그인 추가**: `gstmediafoundation`(권장) + `gstwinks`(MZ0380 선례 검증 소스; 커스텀 winks가 1.22.8 g_assert 회피). 셋 다(mediafoundation/winks/directshow) 존재 확인됨. 의존 base lib 추가 필요 시 `gstreamer.py`에 반영.
- ⚠️ 캡처카드 deviceId 선택(4입력 동일 deviceId) 배선은 **이 마이그레이션 범위 밖**(별도 후속). 회귀 기준 = enumerateDevices가 videoinput 반환 + getUserMedia가 라이브 트랙 반환.

### 5.3 Cargo `gstreamer` crate features

- `["v1_18"]`은 1.28 상위호환 → **무변경**(빌드 통과로 검증).

### 5.4 `windows.py`

- `GSTREAMER_URL`(1.22.8 bootstrap)은 **건드리지 않음**. 단 `mach bootstrap-gstreamer`는 슬롯#1에 1.22.8을 재설치하므로 **실행 금지**를 마이그레이션 노트에 명기.

## 6. §3 — 회귀 검증 매트릭스 (질문 c)

빌드: **debug + release 둘 다** 링크·기동 성공(release는 lld-link 우회 + pkg-config forward-slash 재확인, 월 표출 검증에 필수).

| # | 기능 | 프로브 / 판정 | 비고 |
|---|---|---|---|
| 0 | 빌드·기동 | debug/release exit 0, 기동 시 `ErrorLoadingPlugins` 0 | forward-slash·lld 우회 |
| 1 | P1 확장 이미지(tiff/exr/qoi/jxl) | 이미지 probe, 디코드 성공 | pref on/off |
| 2 | P2 확장 컨테이너(mkv/avi/wmv/flv/ts/mov) | 비디오 probe, 재생 | pref on/off |
| 3 | P3 RTSP(rtsp://) | rtsp probe, 첫 프레임 | RTSP 소스 필요(mediamtx 등) |
| 4 | P4 getDisplayMedia | screen_capture probe, `videoSize!=0x0` advancing | release 월 포함 |
| 5 | 캡처카드(getUserMedia) | enumerateDevices videoinput≥1 + getUserMedia 라이브 트랙, g_assert 없음 | MZ0380/웹캠 필요, 소스 플러그인 등록 후 |
| 6 | 코어 비디오 월(DComp/D3D11) | video_grid(release), lockstep 렌더·패닉0 | 전환이 건드리는 핵심 파이프라인 |
| 7 | WebGL/WebGPU 월 | stress/probe, 렌더 정상 | |
| 8 | 월 스크롤·배리어 무회귀 | wall_sync probe, scroll matched·barrier complete | baseline 대비 |

각 항목: pref 게이트는 on/off 양쪽, 패닉 0, 기대 동작. 로그는 `Start-Process -RedirectStandardOutput/Error`로
확실 캡처(native stdout·UTF-16 함정 회피).

## 7. §4 — 세 질문에 대한 답 (산출물 구조)

마이그레이션 노트(`docs/multigpu/gstreamer_1284_migration_notes.md` 예정)에 아래 3답을 실증 결과로 정리:

- **(a) 핫스왑 side effect & 해소**: 슬롯#1 내용만 1.28.4.100로 바꾸면 → ①`gstreamer.py`가 여전히 1.22.8 DLL 이름(avcodec-59 등)을 찾아 **DLL 복사 단계 실패** ②컴파일은 여전히 1.26.8(env/servo_env 미변경 시) ③슬롯#1을 *비우면* release `-sys` link-search 캐시 붕괴. **해소** = §5.1 이름 갱신 + §4 정션(비우지 않음) + env var 통일.
- **(b) from-scratch 변경점**: target 삭제 시 슬롯#1 정션도 사라짐 → `gstreamer_root()`가 **env var(#2)**로 해석되도록 `GSTREAMER_1_0_ROOT_MSVC_X86_64`(영구) + 커밋된 `gstreamer.py`/`windows.rs.in` 변경이 재현을 보장. `mach bootstrap-gstreamer` 금지.
- **(c) 회귀 결과**: §6 매트릭스 실행 결과.

## 8. §5 — 롤백

비파괴: 정션 해제 + env var 원복 + `gstreamer.py`/`windows.rs.in` git revert → 1.22.8/1.26.8 복귀. 백업한 1.22.8 슬롯#1 내용 복원.

## 9. 비목표 / 리스크

- **비목표**: 캡처카드 deviceId 다중입력 선택 배선, GPU zero-copy(gstgl EGL/ANGLE), WebRTC 라이브 e2e 신규 작업, `winit_wall`(#6)은 별개 사이클.
- **리스크**: ①4.3GB 복사 시간 ②1.28.x 신규 DLL 의존 누락 시 `ErrorLoadingPlugins`(objdump로 curate) ③release 링크 pkg-config 백슬래시(방어됨, 재확인) ④DComp/AMD 경로가 1.28.4.100 gstd3d11 동작 차이에 민감할 가능성(월 회귀에서 확인) ⑤캡처카드 회귀는 하드웨어(MZ0380/웹캠) 가용성에 의존.
